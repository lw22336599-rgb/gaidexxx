# 需求说明
一些实现的功能比如可能是平台特有的功能,也是实现了FunctionBase 或IFunction接口的功能, 用户希望在批量续费或单个续费后, 并根据功能接口指功的针对每个店铺传入的参数自动创建任务提交到后台执行, 以实现续费后自动执行相关功能的需求.

# 解决方案
##  功能接口设计
当前功能接口中已经包含了 StartAsync 方法,以及 Init 传入店铺和配置项数据的方法, 还提供了 ConfType 来获取配置项的类型,可以通过ConfType 来获取jsonschema,从而知道需要传入哪些参数. 通过这些接口,我们可以在续费后根据功能接口的定义,自动创建任务并传入相应的参数.

接口还需增加以下属性:
- 续费后是否自动执行: 当为true时,续费后会自动执行相关功能,前端会根据ConfType生成的jsonschema来收集用户输入的参数,并在续费后自动创建任务提交到后台执行.

配置项设计约定:
- 应只包含值类型(包含string)
- 强制每个属性都要有描述信息,以便前端生成表单时能够展示给用户.

配置项需确认的技术可行性:
- jsonschema是否支持图片?
- jsonschema是否支持枚举?
- NET中有免费的jsonschema生成库吗?是否支持从jsonschema生成表单?

## 功能执行任务表设计
应增加一张表,表要继承支持过期时间父类,2天自动过期,好让程序自动清理过期数据,表应包含以下字段:
- 功能项id: 关联功能项表的id,表示这个续费配置项是哪个功能项的.
- 功能项code: 关联功能项表的code,表示这个续费配置项是哪个功能项的.
- 店铺id: 关联店铺表的id,表示这个续费配置项是针对哪个店铺的.
- 店铺名称: 关联店铺表的名称,表示这个续费配置项是针对哪个店铺的.
- 店铺类型: 关联店铺表的店铺类型,表示这个续费配置项是针对哪个类型的店铺的.
- 参数值: 存储针对店铺的配置参数值,可以是一个json字符串,其中包含了根据功能接口定义的参数要求,针对每个店铺的参数值. 例如可以设计成一个json对象,其中每个属性代表一个参数名称,属性值是这个参数的值.
- 任务状态: 表示这个续费配置项对应的任务的状态,例如可以有待执行、执行中、已完成、执行失败等状态. 后台任务执行完每个任务前后都要更新这个字段.
- msg: 存储任务执行的结果信息,例如成功或失败的原因等. 后台任务执行完每个任务前后都要更新这个字段.
- 执行开始时间: 存储任务开始执行的时间,以便后续查询和统计. 后台任务执行前要更新这个字段.
- 执行结束时间: 存储任务执行结束的时间,以便后续查询和统计. 后台任务执行完要更新这个字段.
- 任务id: 存储hungfire任务id或者t_ls_job_info 的id,以便后续查询任务执行情况和结果. 后台任务执行前要更新这个字段.


## 后台任务类设计
我已经在 AutoRunFuncTask 中声明了任务类

## 任务创建与执行流程
1. 用户在续费界面选择续费的功能项,并根据功能项提供的jsonschema输入针对每个店铺的参数值.
2. 续费完成后,前端会将这些参数值与店铺信息一起提交到后台,后台根据功能接口定义的参数要求来创建任务并执行相关功能. 具体流程如下:
   - 后台接收到续费完成的请求后,首先遍历所有续费的店铺,针对每个店铺根据功能项code和店铺id来创建一条功能执行任务表的记录,并将任务状态设置为待执行,同时存储该店铺的信息和对应的参数值等相关信息.
   - 然后参数其他添加任务的hungfire任务 添加 AutoRunFuncTask

 
##  后端api改动
- 提供获取功能项配置项jsonschema的接口: 续费界面需要根据功能项的配置项来生成表单,因此需要一个接口来获取功能项的配置项jsonschema.
- 批量续费和单个续费的续费完成后,自动获取功能项配置成续费自动执行的功能项,并根据功能接口定义的参数要求,自动创建任务提交到后台执行.
- 增加一个接口来分页查询 t_ls_job_info 中的任务执行情况和结果,以便前端在功能执行中心展示任务执行的进度和结果信息.(按指定功能类型过滤)
- 续费api的参数增加:
	- 是否续费后自动执行相关功能,如果为true则在续费完成后自动创建任务提交到后台执行.
	- 针对店铺的默认参数值,也就是根据功能接口的jsonschema生成表单来输入的参数值,需要提交到后台以便创建任务时使用. 这个参数值会被用来给没有针对店铺单独设置参数值的店铺使用.
	- 针对店铺的参数值(多个店铺的),也就是根据功能接口的jsonschema生成表单来输入的参数值,需要提交到后台以便创建任务时使用.
	
## 前端交互设计
### 配置项的展示与输入
分两部分展示配置:
   1. 当续费的功能项被设置为续费后自动执行时, 选择的续费店铺需要是一个列表,哪么这个列表就要根据jsonschema中的属性来生成列,每行代表一个店铺,每列代表一个参数,用户需要在每行中输入对应店铺的参数值. 续费后,前端会将这些参数值与店铺信息一起提交到后台,由后台根据功能接口定义的参数要求来创建任务并执行相关功能.
   2. 为所有店铺设置相同的参数值: 根据功能项提供的jsonschema来生成一个表单,用户在表单中输入参数值后,续费后前端会将这些参数值与所有续费的店铺信息一起提交到后台,由后台根据功能接口定义的参数要求来创建任务并执行相关功能. 如果店铺没有设置参数就默认用这个参数

### 功能执行中心
 1. 展示所有功能执行任务表的数据,并提供查询和筛选功能,例如可以根据店铺名称、功能项code、任务状态等进行查询和筛选. 每条记录展示店铺名称、功能项code、任务状态、执行开始时间、执行结束时间等信息,并提供查看任务执行结果的功能,例如可以点击查看msg字段的内容来了解任务执行的结果信息.
 2. 提供手动触发功能执行的功能(要支持选择多个店铺手动触发,如果可以还要支持更改参数),例如可以在每条记录中提供一个按钮来手动触发这个任务的执行,以便用户在需要的时候可以重新执行相关功能. 手动触发后,后台会根据功能接口定义的参数要求来创建任务并执行相关功能,并更新任务状态和执行结果信息.
 3. 任务执行进度,展示 t_ls_job_info 中的信息
