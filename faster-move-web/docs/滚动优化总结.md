# ShopTable 滚动性能优化总结

## 📅 优化日期
2026-01-21

## 🎯 优化目标
- 提升滚动性能，减少卡顿
- 简化代码结构，提高可维护性
- 添加调试开关，方便开发调试
- 减少重复触发和不必要的计算

## 🔧 主要优化内容

### 1. 创建专用组合式函数 `useTableScroll`

**位置**: `src/composables/useTableScroll.ts`

**特性**:
- ✅ 统一管理滚动位置的保存和恢复
- ✅ 智能查找滚动容器并缓存（提升性能）
- ✅ 使用节流优化滚动事件监听（100ms 节流）
- ✅ 支持调试模式开关（仅开发环境）
- ✅ 自动管理监听器的添加和移除
- ✅ 带重试机制的滚动位置恢复（最多10次，递增延迟）
- ✅ 完善的资源清理机制

**核心功能**:
```typescript
export function useTableScroll(options: UseTableScrollOptions) {
  return {
    savedScrollPosition,      // 保存的滚动位置
    saveScrollPosition,        // 手动保存滚动位置
    restoreScrollPosition,     // 手动恢复滚动位置
    cleanup                    // 清理资源
  }
}
```

### 2. 重构 `ShopTable.vue`

**优化前**:
- ❌ 700+ 行滚动相关代码
- ❌ 5个独立的 watch 监听器
- ❌ 大量重复的滚动容器查找逻辑
- ❌ 调试日志过多，影响性能
- ❌ 标志位管理混乱

**优化后**:
- ✅ 仅10行代码即可实现所有滚动功能
- ✅ 逻辑清晰，易于维护
- ✅ 自动管理，无需手动处理细节

```typescript
// 使用滚动管理组合式函数（仅需这几行）
const { saveScrollPosition, restoreScrollPosition, cleanup: cleanupScroll } = useTableScroll({
  tableRef: tableRef as any,
  activeTab: activetab_func,
  isLoading: computed(() => props.listLoading),
  dataList: computed(() => props.shopList)
})
```

### 3. 性能优化措施

#### 3.1 节流优化
- **滚动事件监听**: 使用 100ms 节流，减少频繁触发
- **减少 DOM 查询**: 缓存滚动容器引用，避免重复查询

#### 3.2 智能重试机制
- **优化前**: 最多20次重试，每次递增50ms延迟
- **优化后**: 最多10次重试，每次递增30ms延迟
- **总耗时**: 从 ~2.5秒 降低到 ~1.5秒

#### 3.3 调试日志管理
```typescript
// 开发环境可选开启，生产环境自动关闭
const DEBUG_MODE = import.meta.env.DEV && false
```

### 4. 内存管理改进

**优化前**:
- ❌ 多个监听器可能未正确移除
- ❌ 闭包引用过多，容易内存泄漏

**优化后**:
- ✅ 统一的清理机制 `cleanup()`
- ✅ 组件卸载时自动清理资源
- ✅ 标签页切换时自动管理监听器

```typescript
onBeforeUnmount(() => {
  cleanupScroll() // 自动清理所有资源
})
```

## 🚀 使用方式

### 基本使用
```typescript
import { useTableScroll } from '/@/composables/useTableScroll'

const {
  saveScrollPosition,     // 保存滚动位置
  restoreScrollPosition,  // 恢复滚动位置
  cleanup                 // 清理资源
} = useTableScroll({
  tableRef,               // 表格引用
  activeTab,              // 当前激活的标签页
  isLoading,              // 加载状态
  dataList                // 数据列表
})
```

### 手动控制
```typescript

saveScrollPosition()

// 在切换回来后恢复
restoreScrollPosition()

// 组件卸载时清理
onBeforeUnmount(() => cleanup())
```

## 📝 注意事项

1. **调试模式**: 生产环境会自动关闭所有调试日志
2. **内存清理**: 组件卸载时会自动清理所有资源，无需手动处理
3. **自动恢复**: 大多数情况下滚动位置会自动恢复，无需手动调用
4. **兼容性**: 完全兼容现有功能，无需修改其他代码

## 🔮 后续优化建议

1. **虚拟滚动**: 如果数据量超过1000条，考虑使用虚拟滚动
2. **懒加载**: 数据分页加载，减少首次渲染时间
3. **Web Worker**: 将复杂计算移到 Worker 中执行
4. **持久化**: 考虑将滚动位置保存到 localStorage
