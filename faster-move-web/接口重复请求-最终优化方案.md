# 接口重复请求 - 最终优化方案（并发请求去重）

## 问题现象

切换店铺类型时，同一个接口被重复调用多次：
- `GetShopListFunctionColumns?shopType=1` - **重复3次**
- `GetFuncList?shopType=1` - **重复2次**

## 问题根源

### 原因1：多个组件独立调用 API

**问题组件：**
1. `MtFeatureV2.vue` - `loadFunctionOptions()`
2. `MtFeatureV2Functional.vue` - `loadFunctionOptions()`
3. `MtFeatureV2Operation.vue` - `loadFunctionOptions()`
4. `ShopTable.vue` - `filterColumnsByFunction()`

**问题：** 4个组件都调用了相同的API，没有共享缓存。

### 原因2：并发请求问题

**即使使用了缓存工具，仍会出现并发重复请求：**

```typescript
// 时间轴
T0: 组件A调用 getShopListFunctionColumns(1)
    → 检查缓存：无
    → 发起请求 ✅

T1: 组件B调用 getShopListFunctionColumns(1)  (几乎同时)
    → 检查缓存：无（组件A的请求还没返回）
    → 发起请求 ✅ (重复！)

T2: 组件C调用 getShopListFunctionColumns(1)  (几乎同时)
    → 检查缓存：无（请求还没返回）
    → 发起请求 ✅ (重复！)

T100: 组件A的请求返回 → 设置缓存
T101: 组件B的请求返回 → 覆盖缓存
T102: 组件C的请求返回 → 覆盖缓存
```

**结果：** 3次重复请求！

## 解决方案

### 方案1：统一使用缓存工具 ✅

**修改文件：**
- `MtFeatureV2.vue`
- `MtFeatureV2Functional.vue`
- `MtFeatureV2Operation.vue`

**修改内容：**
```typescript
// 修改前
const result = await apiManager.functionappApi.GetShopListFunctionColumns(shopType)

// 修改后
import { getShopListFunctionColumns } from '/@/utils/functionCache.ts'
const result = await getShopListFunctionColumns(shopType)
```

### 方案2：添加并发请求去重 ✅

**修改文件：** `src/utils/functionCache.ts`

**核心机制：**
```typescript
// 正在请求中的 Promise Map
const pendingRequests = new Map<ShopType, Promise<any>>()

export async function getShopListFunctionColumns(shopType: ShopType) {
  // 1. 检查缓存
  if (cache.has(shopType)) {
    return cache.get(shopType)  // 直接返回缓存
  }

  // 2. 检查是否有正在进行的请求
  if (pendingRequests.has(shopType)) {
    return pendingRequests.get(shopType)  // 等待进行中的请求
  }

  // 3. 发起新请求
  const promise = apiManager.xxx.GetXXX(shopType)
    .then(result => {
      cache.set(shopType, result)  // 缓存结果
      pendingRequests.delete(shopType)  // 移除pending标记
      return result
    })
    .catch(error => {
      pendingRequests.delete(shopType)  // 失败也要移除pending
      throw error
    })

  // 4. 标记为进行中
  pendingRequests.set(shopType, promise)

  return promise
}
```

**工作流程：**
```
T0: 组件A调用 → 检查缓存：无 → 检查pending：无 → 发起请求 → 加入pending
T1: 组件B调用 → 检查缓存：无 → 检查pending：有 → 等待组件A的请求 ✅
T2: 组件C调用 → 检查缓存：无 → 检查pending：有 → 等待组件A的请求 ✅
T100: 请求返回 → 所有组件都获得结果 → 设置缓存 → 移除pending
```

**效果：** 只发起1次真正的请求！

**优化前：**
```

📡 GetFuncList?shopType=1                 ← ShopTable
```

## 优化要点

1. ✅ **缓存机制** - 相同参数的结果会被缓存
2. ✅ **并发去重** - 同时多个调用只发起一次请求
3. ✅ **Promise共享** - 并发调用等待同一个Promise
4. ✅ **统一工具** - 所有组件使用同一个缓存工具
5. ✅ **日志跟踪** - 清晰的控制台日志，方便调试
