# 店铺列表排序功能测试清单

## 测试环境
- 浏览器: Chrome/Edge/Firefox
- 设备: Windows 10+

## 基础版测试用例

### 测试用例 1: 基础列头排序功能
**步骤:**
1. 进入门店管理V2 - 基础版
2. 找到"实时收入"列头
3. 点击列头旁边的排序图标(第一次点击)
4. 观察列表刷新

**预期结果:**
- 列表按实时收入从高到低排序(降序)
- 列头显示向下的排序箭头
- 页码重置为第1页
- 加载过渡平滑无闪烁

### 测试用例 2: 切换排序方向
**步骤:**
1. 在"实时收入"列已经降序的情况下
2. 再次点击"实时收入"列头(第二次点击)
3. 观察列表刷新

**预期结果:**
- 列表按实时收入从低到高排序(升序)
- 列头显示向上的排序箭头
- 页码重置为第1页

### 测试用例 3: 取消排序
**步骤:**
1. 在"实时收入"列已经排序的情况下
2. 第三次点击"实时收入"列头
3. 观察列表刷新

**预期结果:**
- 列表恢复默认排序(按更新时间降序)
- 列头不显示排序箭头
- 页码重置为第1页

### 测试用例 4: 不同列的排序
**步骤:**
1. 先点击"实时收入"列头进行降序排序
2. 再点击"实时订单"列头进行降序排序
3. 观察列表刷新

**预期结果:**
- "实时收入"列的排序图标消失
- "实时订单"列显示降序箭头
- 列表按实时订单量从多到少排序

### 测试用例 5: 切换店铺类型保持排序
**步骤:**
1. 在美团餐饮中点击"实时收入"列头进行降序排序
2. 切换到饿了么餐饮
3. 观察排序设置
4. 再切换回美团餐饮

**预期结果:**
- 切换到饿了么时,排序设置为该类型之前的设置(或默认无排序)
- 切换回美团时,仍保持"实时收入"降序
- 列头显示正确的排序图标

### 测试用例 6: 排序与分页
**步骤:**
1. 点击"实时收入"列头进行降序排序
2. 翻到第3页
3. 点击"实时订单"列头更改排序

**预期结果:**
- 排序更改后自动跳回第1页
- 新排序规则生效
- 显示实时订单降序排序的第1页数据

### 测试用例 7: 排序与筛选组合
**步骤:**
1. 先筛选"营业中"的店铺
2. 再点击"实时收入"列头排序
3. 观察结果

**预期结果:**
- 筛选和排序同时生效
- 只显示营业中的店铺,并按收入排序

## 运营版测试用例

### 测试用例 8: 运营数据列头排序
**步骤:**
1. 进入门店管理V2 - 运营版
2. 找到"实时收入"列头
3. 点击列头旁边的排序图标

**预期结果:**
- 列表按实时收入从高到低排序(降序)
- 列头显示向下的排序箭头
- 显示正确的运营数据

### 测试用例 9: 转化率列头排序
**步骤:**
1. 找到"入店转化率"列头
2. 点击列头排序图标

**预期结果:**
- 列表按入店转换率从高到低排序(降序)
- 百分比数据显示正确
- 列头显示排序图标

### 测试用例 10: 多个运营数据列排序切换
**步骤:**
1. 先点击"有效订单"列头排序
2. 再点击"曝光人数"列头排序
3. 最后点击"单均到手"列头排序

**预期结果:**
- 每次排序只有当前列显示排序图标
- 其他列的排序图标消失
- 列表按最后点击的列进行排序

### 测试用例 11: 下单转化率排序
**步骤:**
1. 找到"下单转化率"列头
2. 点击排序图标两次(先降序,再升序)
3. 观察列表变化

**预期结果:**
- 第一次点击:按下单转化率从高到低排序
- 第二次点击:按下单转化率从低到高排序
- 转化率数据正确显示

## 边界情况测试

### 测试用例 12: 空值处理
**步骤:**
1. 点击一个可能有空值的列头(如"单均到手")
2. 先降序排序,观察空值位置
3. 再升序排序,观察空值位置

**预期结果:**
- 降序时,空值店铺排在最后
- 升序时,空值店铺排在最前

### 测试用例 13: 大数据量排序
**步骤:**
1. 在有大量店铺的账号中测试
2. 点击任意列头进行排序

**预期结果:**
- 排序响应时间合理(< 3秒)
- 不出现卡顿或崩溃
- 列头图标状态正确

### 测试用例 14: 快速切换排序列
**步骤:**
1. 快速点击不同列头切换排序
2. 观察列表响应和图标变化

**预期结果:**
- 每次只有一个列显示排序图标
- 最终结果与最后一次点击的列一致
- 没有重复请求或错误

### 测试用例 15: 跨版本切换
**步骤:**
1. 在基础版点击"实时收入"列头排序
2. 切换到运营版
3. 在运营版点击"有效订单"列头排序
4. 再切换回基础版

**预期结果:**
- 切换回基础版时,"实时收入"列仍显示排序图标
- 运营版的"有效订单"排序设置独立保存
- 各版本的排序设置互不影响

## API 请求验证

### 测试用例 16: 请求参数检查
**使用浏览器开发者工具 Network 面板:**

1. 点击"实时收入"列头进行降序排序
2. 查看请求体

**预期请求参数:**
```json
{
  "page": 1,
  "pageSize": 20,
  "order_by": "income",
  "order_direction": 1,
  "filter": {
    "shopType": 1
  }
}
```

3. 第三次点击"实时收入"列头取消排序
4. 查看请求体

**预期请求参数:**
```json
{
  "page": 1,
  "pageSize": 20,
  "filter": {
    "shopType": 1
  }
}
```
(注意: order_by 和 order_direction 应该不存在或为 undefined)
